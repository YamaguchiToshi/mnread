# ADR-0012: 判定 UI の入力はプラトー点の選択のみとし、CPS・MRS は導出値とする

- 状態: 採択（Phase 4）
- 関連: SPEC §5.4、SPEC §5.5、SPEC §8.4、ADR-0005、ADR-0006、ADR-0010

## 文脈

PLAN の Phase 4 は判定 UI の内容を「プラトー点のクリック選択、**CPS/MRS のドラッグ調整**、自動値の併記」と書いている。試作にも CPS 線を掴んで動かす操作があった。

しかし SPEC では、CPS も MRS もプラトー集合 $P$ の関数である。

$$CPS = \min\{L_i^{c} : i \in P\}, \qquad MRS_{\text{arith}} = \frac{1}{|P|}\sum_{i \in P} v_i$$

「CPS 線を $P$ と独立に動かせる」操作を素直に実装すると、この2つの等式が同時に成り立たなくなる。具体的には、$P = \{1.3, 1.2, 1.1\}$ を選んだまま CPS 線だけを 0.8 へ動かすと、**出力の CPS（0.8）と MRS（1.1〜1.3 の平均）が別のプラトーを指す**。この状態は EMR テキストにも書き出しにも出せてしまい、後から読んだ人には矛盾の存在すら見えない。

MRS 線を独立に動かせる操作はさらに悪い。MRS はプラトー内速度の平均であり、ADR-0005 が「実装が3方式のどれかを黙って選ばない」ことを求めている値である。手で動かせる MRS は、その3方式のいずれでもない4つ目の値になる。

## 決定

**判定 UI が受け取る入力はプラトー点の集合 $P$ のみとする。** CPS と MRS は $P$ から導かれた表示であり、独立に編集できる操作を設けない。

`PlateauSelection`（検者の選択）だけが `analyze()` に渡る入力であり、`CpsEstimate` と `MrsResult` は常にその関数である。

**CPS 線のドラッグは残す。ただし操作の意味を写像する。** 線を掴んで動かすと、最も近い**実測サイズにスナップ**し、$P$ を「その段から大文字側への連続区間」として張り直す。動かした結果として CPS と MRS の両方が更新される。検者から見た操作感は試作と同じで、内部で崩れる不変条件がない。

MRS 線にはハンドルを付けない。プラトーの範囲にのみ引き、$P$ の平均であることが見て取れるようにする。

## 根拠

**目視判定は「CPS の値を決める」作業ではなく「どこからプラトーか決める」作業である。** 原典 §3.2 の定義（読書速度が落ちはじめる直前の文字サイズ）も、原典 §5 の指示（MNJA の自動推定がばらつきに弱いので自ら手描きで推定せよ）も、検者が見ているのは点の並びである。値そのものを直接指定させるのは、作業の写しとして正確でない。

**監査の観点でも、記録すべきは「どの点を選んだか」である。** 「CPS を 0.8 にした」だけでは、後から見て妥当性を検討できない。選んだ点の集合が残っていれば、値は再現できる。

**ADR-0010（UI に計算を書かない）とも整合する。** 線の位置から CPS を読み取る実装は、UI 側に「線の座標 → logMAR」という逆変換の算術を持ち込む。スナップ先を実測点の集合から選ぶ形にすれば、UI が扱うのは点の同一性だけで済む。

## 帰結

- PLAN Phase 4 の「CPS/MRS のドラッグ調整」は、**CPS 境界のドラッグのみ**として実装する。この差は本 ADR をもって PLAN への修正とする
- 外れ値は削除ではなく「除外として記録」する（ADR-0006 の踏襲）。除外理由を `exclusionReasons` に残す
- 検者の選択が自動値（`plateau_sdev_v1`）と異なる場合、`overridesAutomatic: true` とし、理由が空なら `OVERRIDE_REASON_MISSING` を立てる
- 「検者がどうしても CPS を手で入れたい」要求が実測検証（Phase 5）で出た場合は、本 ADR を置き換えて対応する。そのときは CPS と MRS が別のプラトーを指しうることを出力上どう示すかを、決定の一部として含める

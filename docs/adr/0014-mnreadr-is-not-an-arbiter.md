# ADR-0014: `mnreadR` との差異は、それ自体では欠陥ではない

- 状態: 採択（Phase 5）
- 関連: ADR-0001（正本の階層）、ADR-0002、ADR-0005、SPEC §5.5.2、`docs/mnreadr-comparison.md`

## 文脈

ADR-0001 は `mnreadR` を「固定版の検証オラクル」と位置づけたが、**照合した結果どうするか**は
決めていなかった。`mnreadR` は英語版 MNREAD チャートの作成者本人（Mansfield・Legge）による
実装であり、「公式なのだから、違うほうを直すべきではないか」という問いは自然に生じる。
実際に生じた。

Phase 5 で実測した結果（`docs/mnreadr-comparison.md`）、この問いに答える材料が出た。

**原典マニュアル §4 の測定例（原典唯一の完全な実測例）で、`mnreadR` のアルゴリズムは
MRS を 412.04 cpm と算出する。原典が本文に記載している値は 411 である。**

CPS とプラトーは三者（`mnreadR` / 原典 / 本仕様）で一致した。食い違うのは MRS だけであり、
そこで `mnreadR` は算術平均側に立ち、原典の記載値から離れる。

つまり `mnreadR` に合わせる操作は、**日本語版マニュアルが自分で書いた値から離れる操作**に
なりうる。理由は明快で、`mnreadR` が公式なのは**英語版 MNREAD** に対してであり、
MNREAD-J / Jk は小田研究室による日本語版だからである。ADR-0001 の階層で `mnreadR` が
4位に置かれているのは、この区別を最初から織り込んでいたためである。

補強材料:

- 2025-10-01 に CRAN から削除（check issues 未修正）。上流は保守されていない。
- `NEWS.md` が自ら記録する major bug: 1.2.0（欠測値処理）、2.1.1（accIndex）、
  2.1.5（MRS の定義変更）、2.1.6（「2.1.5 で入った major bug の修正」）。
- 該当関数内に未使用の変数が残る（`mansfield_algorithm_2021.R` の `smallest`）。
- プラトーの選択は log 空間、MRS の報告は線形空間で、内部でも空間が一貫していない。

## 決定

**照合はする。収束はしない。** `mnreadR` との差異は、それ自体では欠陥ではない。

観測された差異は、必ず次のいずれかに分類する。未分類を残さない。

| 類 | 内容 | 措置 |
|---|---|---|
| A | 英語版固有の定数に由来 | 変更しない（ADR-0001）|
| B | 本プロジェクトが既に裁定済み | 変更しない（該当 ADR を引く）|
| C | 原典に記述があり判定できる | **原典に合う側が正** |
| D | 原典が沈黙している | 変更しない。既知の差異として記録する |
| E | 原典・目視判定に照らして**我々が間違っている** | 修正する |

**コード変更に至るのは E のみ。** 根拠は常に `oda.lab/` に置き、`mnreadR` の挙動そのものを
根拠にしない。E であっても修正は独立した変更として切り出す（SPEC を先に、意図的に変える）。

照合用オラクルは `packages/core/test/oracle/mansfield.ts` に置き、`src/` には入れず
`index.ts` からも export しない。**R ソースの逐条移植をしない** — 移植すると `mnreadR` の
実装バグごと取り込み、測っているのが「アルゴリズムとの差」なのか「バグとの差」なのか
区別できなくなる。`verify-transcription.mjs` が core を import しないのと同じ理由である。
副次的に GPL-2 の派生物の問題も避けられる。

## 根拠

「公式である」は「この用途で正しい」を意味しない。**どのチャートの公式か**が効く。
英語版の権威を日本語版の裁定に流用すると、ADR-0001 が防いでいる静かな値のずれが、
今度は「上流に合わせた」という体裁をまとって入り込む。

同時に、照合をやめる理由にもならない。実際 Phase 5 の照合は本仕様側の実在の欠陥を1件
見つけた（`single_high_outlier` 族で単一の外れ値が核を乗っ取り CPS が過小になる。
`docs/mnreadr-comparison.md` E-1、SPEC §11 OPEN-8）。**照合の価値は収束させることではなく、
自分の弱点を測ることにある。**

## 影響

- 「`mnreadR` と違う」は変更の理由として不十分。A〜E のどれかを示すこと。
- 差異の一覧は `docs/mnreadr-comparison.md` が単一の所在。再測定は
  `pnpm --filter @mnread/core diff:mnreadr`。
- 臨床側から「MNJA / 文献値と違う」と指摘されたとき、この表が切り分けの入口になる。
- `mnreadR` を依存として導入しない。R 実行環境も要求しない。

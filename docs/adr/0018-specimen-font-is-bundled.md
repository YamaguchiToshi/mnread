# ADR-0018: 実物大見本の書体だけを同梱し、他は環境のフォントに委ねる

- 状態: 採択（Phase 5）
- 関連: SPEC §5.7、SPEC §8.2.2、ADR-0017

## 文脈

A4 レポートには**実物大の型見本**（推奨サイズの「読」の字）と **50mm 校正バー**が載る。この2つは体裁ではなく、紙の上で「これが N pt の大きさである」と主張する**計測器**である。バーは倍率のズレ（縮小印刷・用紙違い）を受け取り手が検出するために置かれている。

見本の大きさは2つの量に分かれる。

1. **全角ボディ（em）= N pt** — CSS の `pt` は物理単位なので書体によらない
2. **刷られる墨の高さ = 字面率 × N pt** — 字面率は書体ごとに違う

`--font-mincho` はフォールバック列（ヒラギノ → 游明朝 → Noto Serif JP …）だったため、2 が環境依存だった。実測でヒラギノ明朝 ProN W3 の「読」は 0.913 em、Noto Serif JP は 0.918 em である。**同じ「12 pt」の見本が、院内の PC を替えると違う大きさで刷られる。しかも校正バーはこのズレを検出できない**（バーが見張るのは倍率だけで、字面は動かない）。

発端は「チャートと同じ書体にできないか」という検討だった。MNREAD-J のチャートは**平成明朝体**である（小田浩一「ミネソタ 2016年 初夏 iPad MNREAD-J 始動」NPO東京ライトハウス note、2022-08-02。マニュアル §1.3 と Q&A A5 は「明朝体」としか書いていない）。しかし平成明朝は有償フォントであり、Adobe Fonts の使用許諾は**個々の文字・字形のデザインをそのまま使った製品の作成を禁じている**。グリフを画像・アウトラインとして同梱し、公開リポジトリと GitHub Pages で配る形は、まさにこれに当たる。**採らない。**

## 決定

**実物大見本にだけ書体を同梱する。レポートの他の文字（見出しの明朝を含む）は環境のフォントのままとする。**

- 同梱するのは Noto Serif JP（SIL OFL 1.1）の**「読」1文字のサブセット**。約 1KB、`apps/web/src/assets/mnread-report-mincho.woff2`
- 生成は `apps/web/scripts/build-specimen-font.py`。OFL 全文は `apps/web/public/OFL-NotoSerifJP.txt` に置き、ビルド成果物と一緒に配る
- `font-display: block`。読み込み前に別の書体で描かれると、一瞬とはいえ保証できない大きさの見本が出る
- 見本の大きさは **em に対して**指定する。字面を合わせるための倍率補正はしない（SPEC §5.7）

## 根拠

**環境非依存が必要なのは、物理量を主張している要素だけである。** 見出しがヒラギノで出ようが游明朝で出ようが、誰の判断も変わらない。この線引きにより、同梱するグリフは7字（`読書の評価結果`）から1字に減った。

**「患者が実際に読む書体と一致させる」は原理的に達成できない。** 患者が自分の端末や書籍で何の書体に出会うかは分からない。達成できるのは**再現性**（どの施設のどのプリンタで刷っても同じ紙が出ること）であり、それにはごく一般的な明朝であれば足りる。**したがって書体の選定は低リスクな決定である**——チャートと同じ書体でなくてよい理由も、ここにある。

**忠実性を追う実益も小さい。** ヒラギノと Noto Serif JP の字面率の差は 0.5%（0.913 対 0.918）である。一方、推奨サイズの提示そのものが $[pt(CPS),\ pt(CPS+0.1)]$ ＝ 約 26% の幅を持つ。書体差はこの幅に埋もれる。**再現性は要件、忠実性は要件ではない。**

**外部リクエストは増えない。** サブセットはバンドルに同梱され、同一オリジンから出る。CSP は `default-src 'self'` のままでよく、ADR-0017 の穴（ビーコン1本）は広がらない。Web フォントを CDN から引く案は、この一点で失格である。

## 帰結

- 見本の書体を差し替えたら、**印刷実機で墨の高さを測り直す**。校正バーは倍率しか検出しないので、字面の変化は誰も気づかない。実測値: Chromium `emulateMedia("print")` / 680px 幅で 0.9179 em（fontTools でのフォント側実測 0.9180 em と一致）。A4 実機での印刷は 2026-09-01 に確認済み（校正バー 50mm、倍率の狂いなし）
- 見本の文字を増やすときは `build-specimen-font.py` の `SPECIMEN_CHARS` と `styles.css` の `unicode-range` を両方直す。片方だけだと字が黙ってフォールバックで出る
- `apps/web/test/specimen-font.test.ts` が結線（@font-face の存在・同一オリジン・`.specimen-text` の指定順）を固定する。jsdom は字を組まないので、テストが見張れるのはここまでである
- 平成明朝を使う道は閉じたが、**字面率を測ること自体はライセンスと無関係**である。将来チャート実物を実測し、より近い再配布可能な明朝へ差し替えることは、この ADR の範囲内である

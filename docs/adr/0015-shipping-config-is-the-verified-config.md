# ADR-0015: 出荷構成を受け入れテストの構成にする。指数フィットは暫定主値に昇格させない

- 状態: 採択（Phase 5、2026-08-01）
- 関連: ADR-0006（CPS には算出法IDが要る）、ADR-0012、SPEC §5.5.1・§7・§11 OPEN-9、
  `docs/mnreadr-comparison.md` F-1

## 文脈

`mnreadR` との差異測定の副産物として、照合とは無関係の欠陥が1件出た（F-1）。

`requiresReview` は `CPS_METHOD_DISAGREEMENT`（算出法どうしの食い違い）でも立つため、
**発火率は有効算出法の集合に依存する**。ところが

- `synthetic.test.ts` が「silent-wrong ゼロ」を証明していたのは4手法構成
  （SDev ＋ 指数フィット 80/90/95）
- `apps/web/src/session/derive.ts` は `enabledCpsMethods` を渡さないので、
  出荷されるのは既定の2手法構成（目視 ＋ SDev）

合成600本での実測:

| 構成 | レビュー発火 | 真値からずれ | 無警告 |
|---|---|---|---|
| 合成テストの4手法 | 464 | 117 | **0** |
| 既定（目視＋SDev）| 463 | 117 | **1** |
| 既定＋`expdecay_90` | 464 | 117 | **0** |
| 既定＋指数フィット3種 | 464 | 117 | **0** |

無警告の1本は `noisy_plateau` seed=262327（当方 0.80 / 真値 0.60）。

CLAUDE.md は silent-wrong ゼロを「どの精度指標よりも重要な基準」と置いている。
**その基準が、画面に出る構成では検証されていなかった。**

## 決定

### 1. 出荷構成を受け入れ基準の対象にする

`DEFAULT_ANALYSIS_OPTIONS.enabledCpsMethods` を
`manual_visual_2002` / `plateau_sdev_v1` / `expdecay_90` の3つとする（SPEC §5.5.1）。
最重要基準（silent-wrong ゼロ、無警告なら CPS が ±0.1 logMAR 以内）は
**出荷構成と4手法構成の両方**で走らせる。既定を縮めれば `synthetic.test.ts` が落ちる。

`expdecay_80` / `_95` は入れない。§7 の比較対象は `expdecay_90` のみで
（80/95 は閾値が違う以上ずれて当然なので比較から外してある）、追加してもレビュー発火は
合成600本で1件も変わらない。画面に並ぶ参考値だけが増える。

### 2. 指数フィットを暫定主値に昇格させない

`SELECTION_PRIORITY` を `manual_visual_2002` → `plateau_sdev_v1` で打ち切る。
検者の判定がなく SDev 法も推定不能なら、自動 CPS は表示しない（併記の参考値としては残す）。

## 根拠

**1 について。** 画面に出ない構成で証明した安全性は、出荷の保証ではない。この一点に尽きる。
`expdecay_90` は参考値としてだけでなく、**食い違いを検出する相手**として要る。比較相手が
いない集合では `CPS_METHOD_DISAGREEMENT` は原理的に発火できない。

**2 について。** 元の順序は指数フィットまで降りるようになっていた。既定に入れた瞬間、
それが実際に起きる。合成600本のうち17本で指数フィットが暫定主値に昇格し、**17本すべてが
`sparse` 族**で、その CPS は真値から +0.54〜+0.69 logMAR 外れていた。

これは偶然ではない。SDev 法が推定不能になる主因は欠測段である（SPEC §5.5.2 は
「欠測段をまたがない」を明示的に要求している）。指数フィットは欠測を無視して残った点に
曲線を当てるので、**まさに SDev 法が拒んだ場面でだけ値を出す**。そこを主値に昇格させるのは、
§5.5.2 が拒んだ推定を別の算出法IDで通すことに等しい。

`docs/mnreadr-comparison.md` D-3 は、`sparse` で値を出さないことを「安全な失敗方向」として
裁定した。その裁定を、同じ変更のなかで裏口から開けない。

## 影響と代償

- **原典 §4 の測定例に `CPS_METHOD_DISAGREEMENT` が立つようになった。** 指数減衰モデルが
  二肢曲線に適合せず、90% 到達サイズを実測範囲の外（1.607 logMAR）へ押し出すため、
  SDev の 1.401 との差が 0.206 となり閾値 0.2 をわずかに超える。主値（1.40 logMAR /
  SDev法）と原典の記載値は変わらない。過剰警告側であり、臨床の主値が目視判定である以上
  安全な失敗方向だが、**閾値 0.2 の較正材料としてこの数値を OPEN-6 に残す**。
- 合成600本での既定構成のレビュー発火は 463 → 464。誤発火は `clean_two_limb` で 0/40 のまま。
- 出荷構成で silent-wrong を止めている経路は、**指数フィットの外挿値による食い違い**である
  （55件の発火のうち53件がこれ）。外挿値を比較から外すと seed=262327 が再び無警告に戻る。
  つまりこの防護は強くない。SDev 法自体の弱点（OPEN-8）を直すまでの間の網であり、
  「網があるから曲線を見なくてよい」とは読まないこと。
- `algorithmVersion` 0.3.0 → 0.4.0、`SPEC_VERSION` 0.4.0 → 0.5.0。既定構成の解析結果
  （`cps` の要素数、`requiresReview`、SDev 不能時の `selection.cpsMethod`）が変わるため。
  版が違う JSON は読み込み時に警告される。

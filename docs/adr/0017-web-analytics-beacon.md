# ADR-0017: アクセス解析はビーコン1本に限り、穴はそれが実在するビルドにだけ開ける

- 状態: 採択（Phase 5）
- 関連: ADR-0004（不正入力を拒む）、PLAN Phase 5「公開」、`apps/web/vite/web-analytics.ts`

## 文脈

Phase 5 は臨床レビューを得るために `main` を GitHub Pages へ配信している。**依頼を渡した相手が実際に触ったのかどうかが、開発側からまったく見えない。** 反応がないとき、それが「触ったが問題がなかった」なのか「そもそも開かれていない」なのかを区別できず、次の働きかけを決められない。

一方でこのアプリは、外部接続を**構成として**禁じている。

```
default-src 'self'; …; connect-src 'none'; form-action 'none'; base-uri 'none'
```

`index.html` の注記はこれを「設定ミスで壊せないようにするため」と書いており、README・`docs/review-request.md`・画面の「利用上の注意」の3か所が、医療者に対して「外部への通信は行いません」と明言している。

Cloudflare Web Analytics のビーコン方式は、この CSP と正面から衝突する。`https://static.cloudflareinsights.com` からスクリプトを読み、`https://cloudflareinsights.com` へ送るため、`script-src` と `connect-src` の両方を開けなければならない。

## 決定

**ビーコンを入れる。ただし穴は、ビーコンが実在するビルドにだけ開ける。**

`index.html` は既定の姿のまま（`connect-src 'none'`）置く。ビルド時に `VITE_CF_BEACON_TOKEN` が与えられたときにだけ、Vite プラグインが

1. `script-src 'self' https://static.cloudflareinsights.com` を足し、
2. `connect-src 'none'` を `connect-src https://cloudflareinsights.com` に置き換え、
3. ビーコンの `<script>` を1本足す

の3つを行う。トークンがなければ `index.html` に**一切手を触れない**。

**画面の文言は、ビーコンの有無と同じ変数から出す。** ビーコンが入っているビルドでは「外部への通信は行いません」が消え、何を送っているか（時刻・参照元・画面サイズ／Cookie なし／入力値を含まない）を書いた文へ入れ替わる。

## 根拠

**送るものに患者データが含まれる経路がない。** このアプリは URL に状態を持たず（`location` を参照する箇所がゼロ）、入力値はメモリ上にしかない。ビーコンが送るのは URL・リファラ・UA・画面サイズ・表示速度であり、`/mnread/` という固定の1画面ぶんしかない。Cookie もフィンガープリントも用いない。**したがって変わるのは実害ではなく、医療者に伝えてある保証の内容である。**

**保証の内容が変わる以上、黙って変えてはならない。** ここで守るべきは「外部通信ゼロ」という文字列ではなく、**画面に書いてあることと配信物が一致していること**である。文言をビーコンと同じ変数から出すのは、その一致を人の注意力ではなく仕組みで保つためである。

**既定を素のままにするのは、穴の寿命を最短にするため。** ビーコンを `index.html` へ直書きすると、開発中もテスト中もトークン未設定のビルドも含め、常に穴の開いた CSP が既定になる。差し込み方式なら、トークンのないビルドの成果物は従来と1バイトも変わらない（`pnpm --filter @mnread/web build` の出力で確認済み）。

**サーバ側計測（Cloudflare プロキシ配下の独自ドメイン）なら CSP を触らずに済むが、採らない。** 独自ドメインの取得と DNS の移管が要り、`https://yamaguchitoshi.github.io/mnread/` を配った依頼状が無効になる。レビュー期間中に配布済みの URL を動かす代償のほうが大きい。

## 帰結

- **開けるのは2ホストぶんだけ。** `default-src 'self'` は動かさず、`form-action 'none'` と `base-uri 'none'` もそのまま。`apps/web/test/index-html.test.ts` が、CSP に現れる外部オリジンがちょうどこの2つであることを固定する
- **前提が崩れたらビルドを止める。** 置換対象が見つからない・複数ある・トークンが32桁の16進でない場合は投げる。素通しすると「CSP は開いたのにビーコンがない」「ビーコンはあるのに CSP が塞いでいる」のどちらかを、画面上の手がかりなしに配信しうる
- **計測の停止はコードを触らずにできる。** GitHub のリポジトリ変数 `CF_BEACON_TOKEN` を消せば、次のデプロイから素の CSP に戻る
- **開発サーバにはビーコンを入れない**（`apply: "build"`）。開発中に外部へ ping を打つ必要がなく、`relaxCspForDev` が `connect-src 'none'` を目印にしている
- サイトトークンは秘密ではない（配信 HTML に平文で載る）。`secrets` ではなく `vars` に置く。マスクされないほうが、入っているかどうかを確かめやすい
- **Phase 6 の PWA / オフライン対応で再検討が要る。** ビーコンはオフラインでは単に失敗するので動作に影響はないが、Service Worker の対象から外し、キャッシュに引き込まないこと
- **noindex は外さない**（`index.html`）。アクセス数を見たいことと、検索経路に載せることは別の判断である

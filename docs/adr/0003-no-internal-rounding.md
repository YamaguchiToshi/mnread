# ADR-0003: 内部計算で丸めない

- 状態: 採択（Phase 0）
- 関連: SPEC §9

## 文脈

試作は補正後 logMAR を小数第2位に、RA を小数第2位に丸めた**上で**下流の判定に渡していた。

```js
const adjustedLogMAR = Math.round((nominalLogMAR + delta) * 100) / 100;
RA = Math.round(RA * 100) / 100;
```

公式マニュアルには表示上の丸め（計算例で 0.7967 → 0.8 → 1.1）はあるが、**一般的な丸め規則は規定されていない**。

## 決定

内部計算は倍精度のまま保持し、表示直前にのみ丸める。保存値・比較値・下流入力にはフル精度を用いる。

RA は3系統のフィールドに分離する。

- `raLogMARRaw` — フル精度（保存・テスト対象）
- `raLogMARDisplay` — 小数第2位
- `raLogMARLegacyDisplay` — 小数第1位（旧記録との比較時のみ）

## 根拠

丸めた値を判定に使うと誤差が下流に伝播する。とくに CPS 判定は補正後 logMAR の一致比較を行うため、丸めによって隣接段と同値になりうる。

また、式レベルのゴールデンテストは許容誤差 $10^{-10}$ を用いる（SPEC の計算は四則演算と対数のみで、緩い許容誤差は実装の誤りを隠す）。内部で丸めていると、この精度でのテストが原理的に不可能になる。

RA の誤り1文字あたりの分解能は J で約 0.00333 logMAR であり、小数第2位の丸めはこれより粗い。

## 影響

- 表示関数は `core` の外（UI層）に置き、`core` は丸めた値を返さない。
- スナップショットテストは表示層に対して行い、計算層に対しては数値許容誤差で行う。

# ADR-0010: 計算コアを UI から完全に分離する

- 状態: 採択（Phase 0）
- 関連: PLAN §2

## 文脈

試作は単一の `app.js`（732行）に、計算（`computeAll`）、DOM 更新、チャート描画、EMR テキスト生成、レポート生成が同居していた。

その結果、計算がUI層に漏れていた。たとえば M値換算 `logMARtoM` と推奨倍率の算出 `buildRecommendations` は表示関数の一部として書かれており、テスト対象になっていなかった。実際にこの2箇所に誤りがあった（ADR-0007）。

## 決定

`packages/core` を純粋 TypeScript パッケージとして分離する。

- DOM、日付、乱数、ロケール、`Intl`、環境変数に一切依存しない。
- 全関数が純粋関数。同じ入力から常に同じ出力。
- 丸めた値・整形した文字列を返さない（ADR-0003）。
- **UI層には計算を一行も書かない。** 表示する数値はすべて `core` の返り値から取る。

単位換算・推奨サイズ算出・所見文の数値部分も `core` に置く。「表示のための計算」という例外を認めない。

## 根拠

計算がUIに混ざると、テストの網が届かない場所に臨床値を決めるロジックが生まれる。試作で実際にそうなった。

分離すると、Phase 1 の検証（ゴールデン・境界値・プロパティテスト）を UI の完成を待たずに実行でき、UI の作業中に計算が壊れたことを CI が即座に検出できる。

## 影響

- `core` の返り値の型が UI との契約になる。型を先に固める（Phase 0 の成果物）。
- 所見文のテンプレートは UI 側、埋め込む数値は `core` 側。
- グラフ描画に必要な座標変換は UI 側だが、プロット対象の点集合と CPS/MRS の値は `core` 側。

# mnreadR 2.1.7 との差異と、その裁定（OPEN-3 / Phase 5）

SPEC §5.5.2 が Phase 5 に送った「`mnreadR` 2.1.7 との実際の差異」の測定結果と、
一件ずつの裁定である。

- 再現: `pnpm --filter @mnread/core diff:mnreadr`
- 照合対象の実装: `packages/core/test/oracle/mansfield.ts`（Legge 2007 第5章の記述から起こしたもの。R の逐条移植ではない）
- 位置づけ: **mnreadR は照合対象であって裁定者ではない**（ADR-0014）
- 測定日: 2026-08-01 / mnreadR 2.1.7（2024-01-18, GPL-2, CRAN からは 2025-10-01 に削除）

## 裁定の規則

| 類 | 内容 | 措置 |
|---|---|---|
| A | 英語版固有の定数に由来 | 変更しない（ADR-0001）|
| B | 本プロジェクトが既に裁定済み | 変更しない（該当 ADR を引く）|
| C | 原典に記述があり判定できる | **原典に合う側が正** |
| D | 原典が沈黙している | 変更しない。既知の差異として記録する |
| E | 原典・目視判定に照らして**我々が間違っている** | 修正する（別途） |

## 原典が何を決めているか

裁定の基準になるので先に引く。

**CPS**（マニュアル §3.2, p.4）:

> 通常比較的大きな文字サイズの場合には、読書速度はかなり一定になります。文字を次第に小さくしてゆくと、読書速度が急に落ちはじめる文字サイズがあります。**読書速度が落ちはじめる直前の文字サイズが、臨界文字サイズです。**

**MRS**（マニュアル §3.3, p.5）:

> 臨界文字サイズ以上のときの読書速度の平均値が最大読書速度の代表値です。

**測定例での CPS の決め方**（マニュアル §4.3, p.9）:

> グラフから、文字サイズが 1.1 logMAR より小さくなると、読書速度が低下していくことが解ります。つまり、この患者にとっては、1.1 logMAR が最大読書速度で読める限界のサイズだと**読み取れます**。

つまり原典の方法は**グラフの目視**であり、閾値も最小点数も外れ値の扱いも規定していない。
OPEN-3 が「原典に細則がない」としたのは正しい。ただし §3.2 は**局所的な基準**を与えている —
CPS は「落ちはじめる直前」であって、「最も速い区間の下端」ではない。この差が下記 D-1 と E-1 に効く。

## 測定結果の概要

原典マニュアル §4 の測定例（唯一の完全な実測例）:

| | Legge 2007 法 | 原典の記載値 | `plateau_sdev_v1` |
|---|---|---|---|
| プラトー | 1.3 / 1.2 / 1.1 | 1.3 / 1.2 / 1.1 | 1.3 / 1.2 / 1.1 |
| CPS（補正後）| 1.4010 | 1.4 | 1.4010 |
| MRS | 412.04 cpm | **411 cpm** | 412.04 / 411.27 / 411.27 |

合成曲線 15族 × 40本 = 600本（**下段は E-1 修正後の再測定**、2026-08-01）:

| | 測定時 | 修正後 |
|---|---|---|
| CPS が ±0.1 logMAR 以内で一致 | 408（68%）| **451（75%）** |
| 双方推定できたが 0.1 logMAR 超の相違 | 93（16%）| **50（8%）** |
| `plateau_sdev_v1` のみ推定できた | 59（10%）| 58（10%）|
| Legge 2007 法のみ推定できた | 40（7%）| 40（7%）|
| 双方推定できず | 0 | 1（帯が収束しない曲線）|

潜在真値に近いのは — 測定時が 当方 68本 / オラクル 64本 / 同着 369本、修正後が
当方 68本 / オラクル 23本 / 同着 410本。測定時の所見は「**総体としては互角**であり、
どちらかが一貫して優れているという結果ではない」だった。E-1 を直した後は当方が
外す本数が減っている。**一致率の上昇は目的ではなく副産物である**（ADR-0014）—
直したのは原典 §3.2 の定義に反していた点であって、オラクルに合わせにいったのではない。

## 裁定

### A-1. 読書速度・読書視力・距離補正の定数 — A類

mnreadR は 10語/文、40cm 基準、誤り1つ 0.01 logMAR を用いる
（`R/reading_speed.R`, `R/reading_acuity.R`, `R/viewing_distance_correction.R`）。
本仕様は 30字/24字、30cm、誤り1つ `h/n0`（J で 1/300）。

**措置なし。** ADR-0001 が禁じている当のものである。オラクルはプラトー探索のみを対象とし、
これらの層は最初から比較していない。

### A-2. 計算途中の丸め — A類寄りの B類

mnreadR は距離補正で `round(log10(40/vd), 2)` と、計算の中で丸める。

**措置なし。** ADR-0003（core 内で丸めない）。なお原典の表Aも2桁で与えられており、
本仕様は「フル精度で保持し、表示時に丸める」ことで原典の表示値と一致することを
`verify:fixtures` で確認済み。

### B-1. 0 cpm 点の扱い — B類

mnreadR は `log(rs)` が `-Inf` になる行を解析前に落とす（`R/curve_param.R:131-133`）。
合成曲線 600本のうち **480本（80%）** でこの除去が発生した。原典マニュアル §4 の測定例でも
0.5 logMAR の1点が落ちる。

**措置なし。** ADR-0002（0 cpm は測定事実であり欠測とは違う）および ADR-0011
（原典の図4 が同じ理由で 0.5 の点を落としていることを「繰り返さない」と明記）。
**これは本仕様が意図的に mnreadR と違う箇所である。**

### B-2. MRS が原典の記載値と食い違う — B類

Legge 2007 法の MRS は 412.04 cpm で、これは本仕様の `mrsArithmetic` と完全に同値。
原典が本文に書いた値は **411**（`mrsPooled` / `mrsLegacyMeanTime` 側）。

mnreadR 自身もこの分岐で揺れている。`NEWS.md` 2.1.5（2021）:

> MRS was estimated as the mean of ALL the reading speed measures above the CPS.
> In this fixed version, MRS is now estimated by averaging all reading speed within the optimal plateau

**措置なし。** ADR-0005 の通り3方式を併記する。**mnreadR に合わせることは、原典が本文で
示した値から離れることを意味する。** 片側に寄せない判断はこの1件だけで正当化される。

なお mnreadR は内部でも空間が一貫していない — プラトーの選択は log 速度の平均で行うのに、
MRS は線形速度の平均で返す（`R/mansfield_algorithm_2021.R:87, 110-113`）。

### C-1. ばらつきの下限（`MIN_RELATIVE_SD` = 5%）— C類、本仕様が正

mnreadR には相当物がない。原典は下限を規定していないが、**測定例が数値を与えている** —
プラトー（404.49 / 436.89 / 394.74 cpm）は sd 22.07・平均 412.04 で比にして 5.4%。

SPEC §5.5.2 の 5% はこの実測に由来する。mnreadR 側は下限がないため、窓内の点がたまたま
揃うと `p_std ≈ 0` となり条件が通りやすくなり、**狭い窓に偏る**。予測どおり
`gradual_transition` で顕在化した（下記 D-2）。

**措置なし。原典の実測値に支えられているのは本仕様の側。**

### D-1. 探索の構造 — D類

| | `plateau_sdev_v1` | Legge 2007 法 |
|---|---|---|
| 探索 | 核（隣接2点）＋両方向への拡張＋再推定 | 全区間 `[l,u]` の総当たり O(n²) |
| 選択 | 局所的（核から連続する範囲）| 大域的（条件を満たす窓のうち log 平均最大）|
| 判定 | 内部凝集性（帯の内側か）| 外部分離（窓外の最大 < 窓内平均 − 1.96SD）|

**原典 §3.2 の「落ちはじめる直前」は局所的な記述**であり、その意味では本仕様の構造に近い。
ただし原典は探索手順を書いていないため、どちらが正しいとは決められない。

**措置なし。既知の差異として記録する。** これが OPEN-3 の本体である。

### D-2. `gradual_transition` — D類（双方に弱点、方向が逆）

40本中6本が相違。真値に近いのは当方7 / オラクル10で拮抗するが、**外し方が逆向き**
（E-1 修正後の再測定）:

| seed | 当方 | オラクル | 真値 |
|---|---|---|---|
| 103947 | 0.30 | 0.60 | 0.60 |
| 111866 | 1.00 | 0.60 | 0.60 |
| 238570 | 0.60 | **1.00** | 0.60 |
| 246489 | 0.60 | **1.20** | 0.60 |
| 286084 | 0.50 | 0.80 | 0.60 |
| 301922 | 0.60 | 0.90 | 0.60 |

緩やかな遷移では「落ちはじめる」点が定義上あいまいになる。オラクルは C-1 のとおり
**狭く高い**窓に寄り（1.0〜1.2）、当方は**広く低い**方向に外れる（0.3〜0.5）。

**措置なし。** 原典が沈黙しており、かつこの族は `expectation: "review_required"` で
レビューが発火している。目視判定に回すのが設計どおりの挙動。

### D-3. 欠測段の扱い（`sparse` で当方が 40/40 推定不能）— D類

`sparse` 族では本仕様が全40本で推定不能（「連続する2点の組が存在しない」）。
mnreadR は欠測を無視して残った点だけを並べるため 40本すべてで値を出す。

SPEC §5.5.2 は「欠測段をまたがない」ことを明示的に要求している。原典は欠測に触れていない。

**措置なし。** 値を出さないのは安全な失敗方向であり（誤った CPS がカルテに載るより、
推定不能のほうがよい）、ADR の「Over-flagging is the safe direction」と整合する。
ただし **`sparse` な記録が臨床で頻出するなら再考の対象**であり、Phase 5 の実測で
出現頻度を見る価値がある。

### D-4. 最小点数 — D類

mnreadR は有効点3以下で NA（`R/mansfield_algorithm_2021.R:75, 120`）。
本仕様は `MIN_VALID_POINTS = 4`（SPEC §5.5.4）。**実質同じ。** 原典に規定なし。

**措置なし。**

### E-1. 単一の高い外れ値が核を乗っ取り、CPS が過小になる — **E類（修正済み）**

**本作業で見つかった唯一の実質的な欠陥。** 発見時の記述を残し、末尾に措置を記す。

`single_high_outlier` 族で 40本すべてが相違し、**40本すべてでオラクルのほうが真値に近い**。

機序（seed=1000、真値 CPS = 0.6）:

```
1.3:380  1.2:380  1.1:380  1.0:722  0.9:380  0.8:380  0.7:380  0.6:380
0.5:190  0.4:95   0.3:48   0.2:24   0.1:12   0.0:6    -0.1:3   -0.2:0
                    ↑ 外れ値
核 = {1.1, 1.0}   level = 551.0   sd = 241.8   帯の下限 = 77.0 cpm
当方 plateau = 1.3 … 0.4   → CPS = 0.4   （真値 0.6）
ｵﾗｸﾙ plateau = 1.3 … 0.6   → CPS = 0.6
```

核は「平均が最大の隣接2点」なので、**単一の高い外れ値があれば必ずそれを含む組が核になる**。
核は2点しかないため、その標本 sd は外れ値の逸脱量だけで決まる（`|722−380|/√2 = 241.8`）。
帯の下限が 77 cpm まで下がり、真の CPS より下の 0.5（190）と 0.4（95）まで飲み込む。

再推定は区間全体からばらつきを求め直すが、**広がった区間の sd はさらに大きくなるため
引き戻されない。**

裁定: 原典 §3.2 の「読書速度が落ちはじめる直前の文字サイズ」に照らせば、この曲線の
CPS は 0.6 である。**本仕様の 0.4 は原典の定義に反する。**

臨床的な向き: CPS の**過小**評価であり、患者が最大速度で読めるサイズより**小さい**文字を
推奨する方向。これは危険な向きである。

緩和されている点: `requiresReview` が 40/40 で発火しており、silent-wrong ではない。
臨床の主値は目視判定（`manual_visual_2002`）であり、自動値がそのままカルテに載る設計ではない。

**措置: 修正済み（2026-08-01、ADR-0016 / SPEC §5.5.2 / OPEN-9 とは別に OPEN-8 を解決）。**

帯の水準とばらつきを、区間の**最速1点を除いた**標本から求める（区間が4点以上のとき）。
あわせて**プラトーを再推定の不動点として定義**し、巡回した場合は推定不能とした。

`single_high_outlier` は 0/40 → 40/40 が真値と完全一致。他14族に退行はない
（完全一致で下がったのは `gradual_transition` の 20 → 18 のみで、±0.1 では同数）。
合成600本の完全一致は 457 → 498。

**検討の過程で分かったこと**（ADR-0016 に詳細）:

- 「最速点を散らばりからだけ除く」案は精度指標では 40/40 に見えたが、実際には反復が
  **振動して収束していなかった**。±0.1 logMAR の許容が「10回目にたまたま隣に居た」を
  正解として数えていた。**指標が設計の破綻を隠した。** 収束性を独立に測って気づいた。
- 「自己整合な区間を宣言的に列挙する」案は 115/600。CLAUDE.md が記録している
  「捨てた設計1」（長いプラトーを 0.95ⁿ で構造的に棄却する）が実測で再現した。
- 中央値+MAD・片側偏差はいずれも、原典測定例で下限 5% が常に効くようになる。
  **下限の根拠になっている当の計算を骨抜きにする**ため採らなかった。

変異11件（除外なし / 落とす側を最遅に / しきい値 4→2 / 不動点の要求なし /
除外を散らばりだけに、の新規5件を含む）すべてがテストで検出される。

## mnreadR とは無関係の独立した所見

### F-1. 画面の既定構成が、受け入れテストより弱い

差異測定の副産物として見つかった。**mnreadR とは関係がない。**

`requiresReview` は算出法どうしの食い違い（`CPS_METHOD_DISAGREEMENT`）でも発火するため、
発火率は**有効な算出法の集合に依存する**。

| 構成 | レビュー発火 | 真値からずれ | 無警告 |
|---|---|---|---|
| `synthetic.test.ts` の4手法 | 464/600 | 117 | **0** |
| 既定（`manual_visual_2002` + `plateau_sdev_v1`）| 463/600 | 117 | **1** |
| 既定 + `expdecay_90` | 464/600 | 117 | **0** |
| 既定 + 指数フィット3種 | 464/600 | 117 | **0** |

無警告の1本は `noisy_plateau` seed=262327（当方 0.80 / 真値 0.60）。

> 表の数値は E-1 修正**前**の測定である。修正後は 456/600・ずれ 73 になるが、**構成による差は
> そのまま残る**（旧既定だけが seed=262327 を無警告で通す）。依存そのものが消えたわけではない。

`apps/web/src/session/derive.ts:125` は `analyze()` に `enabledCpsMethods` を渡していないため、
`DEFAULT_ANALYSIS_OPTIONS` の**2手法構成で出荷されている**。一方 `synthetic.test.ts` が
「silent-wrong ゼロ」を証明しているのは**4手法構成**である。

CLAUDE.md は silent-wrong ゼロを「どの精度指標よりも重要な基準」と位置づけている。
その基準が、画面に出る構成では検証されていない。

**措置: (c) 両方。2026-08-01 に対処済み（ADR-0015、SPEC §5.5.1、OPEN-9 解決）。**

- 既定の有効算出法を 目視 / SDev / `expdecay_90` の3つにした。`expdecay_80` / `_95` は
  入れない — §7 の比較対象が `expdecay_90` のみで、追加しても発火は1件も変わらない。
- 最重要基準（silent-wrong ゼロ、無警告なら ±0.1 logMAR 以内）を**出荷構成でも**走らせる。
  既定を縮めると `synthetic.test.ts` が落ちる。
- あわせて `SELECTION_PRIORITY` を SDev で打ち切った。既定に指数フィットを入れると、
  SDev が推定不能な場面で指数フィットが暫定主値に昇格する。合成では17本すべてが
  `sparse` 族で、CPS は真値から +0.54〜+0.69 logMAR 外れた。D-3 で「値を出さないのが
  安全な失敗方向」と裁定した当のものを、同じ変更の裏口から開けないため。

**代償を明記する。** この防護は強くない。既定構成の `CPS_METHOD_DISAGREEMENT` 55件のうち
**53件は指数フィットの外挿値（実測範囲外）が原因**であり、外挿値を比較から外すと
seed=262327 は再び無警告に戻る。副作用として原典 §4 の測定例にもフラグが立つ
（SDev 1.401 対 指数フィット 1.607、差 0.206 が閾値 0.2 をわずかに超える）。
閾値の較正は実測20〜30例で行う（OPEN-6）。**本質的な修正は OPEN-8 の側にある。**

## 未分類の残り

**なし。** 観測されたすべての差異が A〜E および F に分類されている。

## まとめ

- 原典マニュアル §4 の測定例では **CPS が三者一致**。MRS のみ mnreadR が原典と食い違う（B-2）。
- 合成曲線では測定時点で**総体として互角**（真値に近いのは当方68 / オラクル64 / 同着369）。
  E-1 修正後は 当方68 / オラクル23 / 同着410。
- **mnreadR に合わせるべき差異は1件もなかった。** A・B は意図的な相違、C は本仕様が原典に支えられ、
  D は原典が沈黙している。
- 一方で **E-1 は実在の欠陥**であり、mnreadR との照合がなければ見つからなかった。
  照合の価値はここにある — 収束させることではなく、自分の弱点を測ることにある。
- 付随して F-1（出荷構成の検証不足）を発見。mnreadR とは無関係だが、臨床上の優先度は高い。
- **3件とも 2026-08-01 に処理した。** F-1 → ADR-0015（OPEN-9 解決）、E-1 → ADR-0016
  （OPEN-8 解決）。D 類の既知の差異（探索の構造・`gradual_transition`・`sparse`・最小点数）は
  記録として残る。次に見直す材料は、合成曲線ではなく Phase 5 の実測20〜30例である。

## 追記（2026-08-31）: 照合対象の射程 — iPad 版アプリも同じアルゴリズムだった

Calabrèse et al. (2018), *Comparing performance on the MNREAD iPad application with the MNREAD
acuity chart*, Journal of Vision 18(1):8（`references/i1534-7362-18-1-8.pdf`）が、"MNREAD parameters
estimation"（p.4–5）で次を明記している。

> Both methods used the same calculations: MRS and CPS were estimated using the original
> algorithm described in Legge (2007) …

紙のチャートのデータは `mnreadR` で、iPad はアプリ内でリアルタイムに解析され、**両者は同じ計算**。
つまり **iPad 版アプリの自動推定 = `mnreadR` = Legge 2007 法**であり、本ドキュメントの照合対象
（`packages/core/test/oracle/mansfield.ts`）は、そのまま iPad 版アプリの照合でもある。

**裁定は1件も変わらない。** A〜E の分類は原典マニュアルと Legge 2007 法の突き合わせであって、
その法をどの製品が積んでいるかには依存しない。変わるのは照合対象の位置づけだけである —
比較していた相手は R パッケージ1本ではなく、英語圏で現に臨床運用されている実装だった。
ADR-0014（**照合対象であって裁定者ではない**）はそのまま維持する。日本語版マニュアルが自分で
書いた値から離れる変更は、相手が iPad 版アプリでも採らない。

### この論文が Phase 5 に与える外部の目安

**1. 自動推定は目視で覆される前提で運用されている。** 論文自身が、アルゴリズムの推定を目視検査で
「誤り」と判定した割合を報告している。

| | 紙チャート（mnreadR）| iPad アプリ |
|---|---|---|
| 実験1・正常視（N=165）| 4% | 2% |
| 実験2・ロービジョン（N=43）| **11%** | **9%** |

アプリ側にも手動上書きの経路がある（"the examiner had the option to override the automatic fit
and perform a manual estimation"）。本アプリの構成と同じである — 主値は視能訓練士の目視
（ADR-0006）、自動推定は併記、上書きに理由を付す。

当院の対象はロービジョン寄りなので、**目安になるのは 9〜11% の側**。`requiresReview` の発火率が
これを大きく下回るなら、閾値が緩すぎることを疑う材料になる（OPEN-6 / OPEN-7 の較正時に使う）。

**2. 目視で覆すときの規則が、こちらの判定モデルと同じ。**

> MRS was estimated as the plateau of the curve, and CPS was set as the last print size
> sustaining MRS.

MRS も CPS もプラトー点集合 `P` の関数である。ADR-0012（判定 UI の入力は `P` ただ一つ、CPS 線に
独立のハンドルを与えない）を外から裏づける。

**3. グラフは log 読書速度 × 文字サイズ。** アプリの結果画面も "the corresponding MNREAD curve of
log reading speed as a function of print size"。ADR-0011 と同じ空間である。

### 持ち込まないもの

論文は英語版 MNREAD の測定であり、定数はすべて英語版のもの（wpm、40cm 基準、ACC の 18–39 歳
基準値 1.0）。ADR-0001 / ADR-0008 の線はそのまま。とくに、iPad の ACC を紙に合わせるための
**係数 1.1（"a multiplicative factor of 1.1"）は日本語版とは無関係**であり、持ち込まない。

もう一点、将来のために記録しておく。論文は MRS の紙・iPad 差（速い読者ほど大きく、250 wpm で 12%）を
**計時方法の差**に帰している — ストップウォッチ計時は開始が遅れるぶん読書時間を過小に、速度を過大に
出す。本アプリが受け取るのは紙チャート＋ストップウォッチの計時なので、デジタル計時の値と本アプリの
値を直接比べる場面が来たら、この偏りを差し引く必要がある。**現時点で修正すべき箇所はない。**
